# Picaso：桌面首版需求与技术选型

本文是当前基线。[实现计划](implementation-plan.md)描述交付顺序；`research/` 保留参考项目的源码分析，其中较早的 Next.js / Electron 方案不是发行架构。

## 用户要完成的事

- 优先面向没有技术背景的 macOS 用户。首个内部包支持 Apple Silicon，打开磁盘映像后将 Picaso 拖入 Applications 即可，不需要另装 Node、Rust、手动配置 `.env` 或启动本地服务。
- 首版使用用户自己的 OpenAI API Key 和 API 额度。默认服务商是「OpenAI（官方）」，提供能生图和编辑的默认模型，不要求填写接口地址或模型名。
- 输入提示词生成图片，可以查看历史、保存原图。从历史中选择**一张**结果图，写新指令并提交，得到一份新结果。原图和原任务不变，重开应用、覆盖升级后仍能从旧图继续修改。
- 仅在用户明确提交生成或修改时发起付费生图请求。打开应用、保存配置、查看历史、点「继续修改」都不应触发请求。

## 首次启动与密钥来源

| 情况 | 行为 |
|---|---|
| 首次启动，当前进程能读到 `OPENAI_API_KEY` | 告知「检测到 OpenAI 密钥，来源：环境变量」，让用户选择使用它或改为手动输入。选择环境变量时只记住来源，不复制密钥值。 |
| 首次启动，没有环境变量 | 展示遮蔽输入框、[官方密钥管理入口](https://platform.openai.com/api-keys)及计费说明：额度来自 OpenAI API 账户，与 ChatGPT 订阅分开。手动输入后在本机按当前系统用户保护并保存，不写入环境变量。 |
| 再次启动 | 已配置则直接进入工作台。设置可查看当前来源、切换来源、更换或移除应用保存的密钥。用户明确选择的来源优先；不可用时提示修复，不能静默换账户，也不应阻止浏览已有图片。 |

保存配置不试生图、不声称已验证余额或模型权限。设置不回显现有 Key，日志、图库、导出文件和安装包都不包含明文密钥。

## 发行架构

- **桌面：** Tauri 2，macOS 首包采用系统 WKWebView，交付 Apple Silicon 的 `.app` 和 `.dmg`。Windows x64 的 WebView2 与当前用户 NSIS 安装包验收顺延。包体以实际构建测量，不预设未经验证的大小。
- **界面：** Vite + React + TypeScript + Tailwind CSS + shadcn/ui；颜色取自 [`refs/claude.css`](../refs/claude.css)，布局参考 Arknights Techwear 的 Field 工业工作台。Node 只用于开发和构建，不随应用运行。
- **本机逻辑：** Rust 负责密钥、OpenAI Images API、任务与文件。前端通过受限 Tauri 命令提交任务，不直接调用供应商；无 Node sidecar、无本地 HTTP 服务。M1 在 macOS 使用用户钥匙串保存手动 Key，Windows 版本沿用当前用户范围的 DPAPI。
- **数据：** SQLite 保存任务、模型、参数和图片引用，原图放用户应用数据目录，与程序安装目录分离。历史编辑只提交图片 ID，Rust 读取受管理的原图，不让前端来回搬运文件。
- **扩展：** 用 `(providerId, modelId)` 标识模型，按模型描述能力，按供应商适配请求和结果。首版只交付 OpenAI；将来新增模型无需改图库。若模型不支持参考图编辑，应在提交前说明，不丢弃参考图、不自动换供应商。
