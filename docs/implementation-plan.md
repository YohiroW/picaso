# Picaso v0.1 实现计划：从安装包到第二张图

**原定公开发布标准：** 给一位没有开发环境的 Apple Silicon Mac 用户一个 `.dmg`。他能看懂密钥来自哪里、用自己的额度生成第一张图，重开后选中这张图改出第二张；覆盖升级后两张都在。需求以[首版基线](requirements.md)为准。M0 的实际结果见[安装验证记录](m0-macos.md)，M1–M4 已实现，M5 按本次约定交付本机验证的开发版，结果见[开发版验收](development-build.md)。

本次 M5 验收范围已调整为 Apple Silicon 本地开发版。使用真实生成和历史编辑产生的数据验证覆盖升级，检查本地签名与 DMG，交付校验值和使用说明。Developer ID、公证、干净机器与独立用户验收留待将来决定正式分发时进行。

## 里程碑与验收

| 顺序 | 可交付的结果 | 如何判定完成 |
|---|---|---|
| **M0 · macOS 首个安装包** | 在仓库根建立 Tauri 2 / Vite / React / TS 工程，保留 `refs/` 只读。定义应用标识与用户数据目录，使用本地主题，在窗口显示 Rust 返回值。构建 Apple Silicon release 应用与 DMG。 | 挂载 DMG，将应用复制到 Applications，从副本启动，验证窗口显示后端返回的版本与数据路径。记录实际包体、系统 WebKit 使用情况、签名状态与测试机环境。Windows x64 当前用户 NSIS 包和 WebView2 已有、缺失联网、缺失离线三种场景保留为后续平台验收。 |
| **M1 · 用户知道将使用哪把 Key** | 完成引导页与密钥设置。Rust 探测环境变量，只向界面返回来源与可用状态。手填值通过专用命令交给 Rust，存入 macOS 用户钥匙串；提供更换、移除及显式切换来源。 | 覆盖无环境变量、仅环境变量、手填后重启、两种来源并存、所选来源消失。环境变量值不落盘，不能因设置失效而静默改用另一把 Key。用虚构测试密钥验证日志和普通配置无明文；全流程对图片接口调用 **0 次**。 |
| **M2 · 本地跑通生成和存档** | 定义模型目录和最小供应商接口；先接仅供测试的假供应商。一次提交写一条任务，把固定测试图片落盘并显示在历史中。实现历史查询、单图预览和另存为。 | 无网无真实 Key 的测试也能运行。重开应用后，历史仍能显示原图、提示词、provider/model；导出的图片可独立打开。模拟写盘失败时不将任务标为成功。 |
| **M3 · 历史单图继续修改** | 点某张图的「继续修改」只把该图加入草稿，显示来源缩略图并聚焦新指令。再次提交才创建任务。历史列表、预览和输入区构成主工作台，设置不占用主操作区。 | 假供应商让任务 A 返回 `a1/a2`：选 `a2` 时请求计数不变，提交后只收到一次编辑请求，输入确为 `a2` 原图而非缩略图或整批图。新任务 B 指向 `a2`，A 未变；仍能从 `a2` 改出另一版。源文件缺失或模型不支持编辑时保留草稿、发出 **0 次**请求。 |
| **M4 · 接通 OpenAI** | Rust 用 `reqwest` 实现生产适配器，仅调用官方 `/v1/images/generations` 和 `/v1/images/edits`。选定同时支持两项操作的默认模型，发行前核对其可用参数。把 Key 无效、权限不足、额度不足、限流、网络失败映射为不同的用户操作提示。 | 先用本地 HTTP 测试替身验证生成请求、带原图的编辑请求及错误响应，发布包不暴露可配置中转地址。自动测试不使用真实 Key。待用户明确同意消耗额度，再用小规模真实请求走通一次生成、一次历史编辑，记录模型和结果，不记录密钥。 |
| **M5 · 交付给普通用户** | 完成安装、重启、升级和恢复测试；核对发布者、签名与真实安装提示。发布一个带版本号的安装包，附简短使用说明和校验值。 | 让未参与开发的人仅凭安装包和自己的 Key 走通发布标准；覆盖安装测试保留密钥来源、SQLite 数据、原图及引用关系。对候选版本重新记录包体。内部未签名测试包与面向普通用户的正式包明确区分。 |

M0 是第一个决策点：先验证选择 Tauri 所期待的分发收益。M2–M3 是第一个可演示的完整工作流，不依赖 API 额度；M4 替换供应商实现，不重写界面或历史数据。

## 实现时保留的三个接口

| 位置（拟） | 负责 | 不负责 |
|---|---|---|
| `src/features/{onboarding,workspace,history}` + `src/lib/desktop.ts` | React 管理草稿、选中的图片和展示状态。将 Tauri 调用集中到一处，例如查询凭据状态、提交任务、列出历史、导出图片。 | 不读环境变量，不持久化 Key，不直接写 SQLite，也不以文件路径作为历史图身份。 |
| `src-tauri/src/{credentials,providers}` | 凭据模块按显式来源取值。模型目录声明生图、参考图编辑等能力；供应商接口接收模型、提示词、参数和可选的原图，返回图片与可得用量。生产实现为 OpenAI，测试实现返回固定图片并记录调用。 | 不把 Key 放进任务快照；不为尚未接入的供应商做插件加载器或配置页面。 |
| `src-tauri/src/{jobs,library}` | `jobs` 验证能力和引用、创建任务、执行一次请求；`library` 用 `rusqlite` 管理版本化 schema、用本地文件保存图片。一个任务可有多个输出，一张图片可被不同后续任务引用。 | 不在 Tauri 命令里重复写落盘逻辑；不覆盖旧图，不让前端传任意路径读取本机文件。 |

**提交语义：** 前端一次提交产生一个请求 ID，本机按该 ID 去重；点击按钮后禁用重复提交。任务记录保存 provider/model、实际提交参数、输入图片 ID、状态、输出和可得用量。结果先写临时文件，再移入图库并提交数据库记录；重启时识别未完成任务和孤立文件。若超时或退出时无法确认供应商是否已处理，显示「结果未确认，重新提交可能再次计费」，不自动重发。这是本机去重，不承诺上游恰好扣费一次。

**界面与权限：** 大图预览是主体，历史是索引，生成/修改是唯一主动作；保留 Claude+ 暖色与细分隔线，检查浅色按钮文字对比度。走通中文输入法、键盘选图与提交、系统显示缩放。Tauri capabilities 只向本地主窗口开放所需操作；SQL、任意读写、供应商 HTTP 和解密不作为通用前端命令。

## 发布前的验证与范围

- **自动化：** Rust 测凭据来源优先级、模型能力、任务去重、SQLite 迁移和引用关系；HTTP 替身测 OpenAI 协议；React 用 Vitest 测引导状态及「选图不提交」。`cargo test`、前端类型检查/测试和 release 构建通过，才能出候选包。
- **人工验证：** 干净 Apple Silicon Mac；从 Finder 和从带临时环境变量的终端分别启动；用旧版测试数据覆盖升级；验证有/无网络情况下均可查看旧图。签名凭据、验证机和真实 API 冒烟测试的授权是发行前置条件，不是本地开发前置条件。
- **首版不做：** 第二个生产供应商、任意 Base URL、账号/云同步、Agent 对话、遮罩画板、批量队列、流式预览、自动更新、独立网页版。升级先支持手动覆盖安装；首个目标为 Apple Silicon macOS；Windows x64 的安装体验在该平台单独验证。
